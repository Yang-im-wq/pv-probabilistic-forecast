# 原理说明：从点预测到概率预测，以及它如何服务分布鲁棒优化

---

## 1. 为什么需要概率预测，而不是点预测？

传统预测（点预测）回答的是：**"下一时刻功率大概是多少？"** 它只给一个数，比如 350 kW。

但光伏出力受云团遮挡影响，波动极大且不可精确预知。同样是"预测 350 kW"，一个万里无云的日子和一个乌云翻滚的日子，可信度完全不同。点预测把这个信息丢掉了——它把一个有噪声、有分布的真实量，硬压成了一个确定值。

概率预测回答的则是：**"下一时刻功率最可能落在哪个范围？这个范围有多宽？"** 它给出的是一个**预测分布 / 预测区间**，比如"有 90% 的概率在 280–420 kW 之间"。

对下游的优化决策来说，这个差别是决定性的：**决策者需要知道不确定性有多大，才能既不过分冒险、也不过分保守。** 点预测给不了这个信息，概率预测可以。

---

## 2. Pinball Loss 的直觉

要输出预测区间，最直接的想法是"学两条线"：一条上界（q90，希望有 90% 的真实值落在它下面）、一条下界（q10，希望有 10% 落在它下面），中间再加一条中位线（q50）。

难点在于：怎么让网络"知道"这条线该偏上还是偏下？答案就是 **Pinball Loss（分位数损失）**：

- 对 q90 这条线，如果它**偏低**（真实值跑到它上面了），要重罚——因为 q90 的职责就是"罩住 90% 的真实值"；
- 如果它**偏高**，只轻罚——稍微偏高一点没关系，别偏太多即可。

于是 q90 被训练成"宁可偏高一点"、q10 "宁可偏低一点"，q50 则对称惩罚、落在中间。三条线合起来，就框出一个 90% 预测区间。

一句话记法：**分位数损失用"不对称的惩罚"告诉模型——这条线该站得高一点还是低一点。**

---

## 3. PICP 和 PINAW 分别衡量什么、怎么读

评价一个预测区间好不好，要看两件事：**准不准覆盖**、**宽不宽**。它们常常矛盾，必须一起看。

- **PICP（覆盖率）**：真实值落在预测区间内的比例。标称 90% 的区间，PICP 越接近 0.9 越好。
  - 太低（如 0.5）→ 区间"说谎"，一半真实值都跑出去了，不可信。
  - 太高（如 1.0）→ 区间放太宽，什么都罩住，等于没说。

- **PINAW（归一化区间宽度）**：区间平均宽度占目标极差的比例，越小越好。
  - 一个把所有可能值都包进去的"超宽区间"也能 PICP=1，但毫无信息量；
  - PINAW 就是用来惩罚这种"作弊"的。

**好的结果是：在 PICP 接近标称值（0.9）的前提下，PINAW 尽量小。** 这代表区间"又准又紧"。

（本项目额外算了一个 CRPS，是比 PICP/PINAW 更综合的"分布级"打分，这里不展开。）

---

## 4. 这个输出如何被下游的分布鲁棒优化（DRO）使用？

分布鲁棒优化的思路是：不确定参数（这里是光伏出力）的真实分布不知道，于是构造一个**模糊集（ambiguity set / 不确定集）**——一个"可能分布的集合"，然后优化"在最坏分布下的表现"，保证解对所有可能分布都稳健。

模糊集怎么构造，直接决定解是保守还是激进，而**构造模糊集恰恰需要知道"分布大概长什么样"**：

- 如果上游只给一个**点预测**，DRO 只知道一个均值点，只能构造一个非常宽、非常保守的模糊集（否则容易把真实分布漏出去），代价是调度方案过分保守、浪费资源；
- 如果上游给的是**概率预测（分位数/预测分布）**，DRO 就能构造一个**更紧、更数据驱动的模糊集**——比如用预测出的 q10/q90 确定支撑集的边界、用分位数确定矩的约束、把 Wasserstein 球的中心锚在预测分布而非单点上。结果是在同样的稳健性下，决策更"紧"、成本更低。

**一句话总结**：概率预测输出的分布，把 DRO 里那个"人为拍脑袋"的模糊集，变成了"从数据里学出来的"模糊集——稳健性不打折，保守性显著下降。这就是"预测模块"对下游优化最直接的价值。
